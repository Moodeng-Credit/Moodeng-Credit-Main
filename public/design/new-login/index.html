How people sign up and get in

Most borrowers arrive from a Facebook post and open Moodeng inside Facebook's or Messenger's own browser, where Google sign-in can't work. Filipinos there sign up with their mobile number and a text code that lands on the same phone (the keyboard offers it, so nobody leaves Facebook). Email sign-up still needs no code until they're approved, because reading an email does mean leaving Facebook. Each flow below is a scenario: Given the situation, When they do something, Then what they see, with why the flow exists and where it's offered.

Phone or email to start Phone: one text code, right there Email: no code until approved Smart / TNT / Sun → email, for now Codes come from "Unisoft"

Who sees what

Two things decide the screens: where they opened Moodeng, and whether they look like a visitor in the Philippines (phone set to Manila time, a Philippine language or region, or Filipino picked in our language menu). Phone codes only work for Philippine numbers, so everyone else gets email.

1Sign up with a mobile number inside Facebook (text code)

Why: the email box was where people stopped. In the first days of email sign-up inside Facebook, 18 people saw it and only 10 sent it (team tests included, so a rough number). Everyone there has a phone number and types it faster than an email. A text code is fine here: it arrives on the same phone, the keyboard offers it (iPhone) or it pops up at the top (Android), so they never leave Facebook. It also proves the number is theirs and makes a normal account straight away. About ₱0.50 a sign-up.

2Smart, TNT and Sun numbers go to email

Why: our texts go out through UniSMS on its shared "Unisoft" sender name. Semaphore banned our own names, and a sender name of our own needs Philippine business papers. That shared sender can't reach Smart, TNT or Sun, which is roughly half of the Philippines. Rather than let someone sign up with a number we can never text, we say so before they tap.

8Reminders, and what we fill in for them

Why: Messenger is how we reach borrowers, so it stays required. Phone notifications don't work inside Facebook's browser, so there they pick WhatsApp, or Viber or Telegram after "I don't have WhatsApp". SMS can't carry reminders yet: the shared Unisoft sender only sends sign-in codes. Anything we already know, we fill in, so there's less to type.

Switches, if something needs to go back: phone sign-in everywhere: SMS_LOGIN_ON in src/lib/phoneAuth.ts (?sms=0 turns it off in one browser for testing). Texts: Vault UNISMS_SECRET_KEY + UNISMS_SENDER_ID (without the key, the text hook falls back to Semaphore, which sends nothing).

To turn it on

1. Meta approves the 3 messages (WhatsApp Manager → Message templates says Approved). 2. Add about $5 in SendPulse, with auto-recharge off. 3. Flip borrower_whatsapp_enabled to true. 4. Test from a second phone: send the code, receive a reminder, send STOP.
