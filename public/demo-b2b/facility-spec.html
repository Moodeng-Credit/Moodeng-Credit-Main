Facility & reserve: the smallest true slice

What has to exist before the partner-lender demo stops being a mock. Two tables, three functions, one rule. Everything else in the console already has a live counterpart in production.

01

Why this slice

scope fence

The console's core loop is: draw capital → issue loans → charge-offs eat reserve → coverage falls → draws get declined. Money movement, identity, scoring and note custody are already live. The only fictional parts are the facility, the reserve, and the gate between them. Build those three and the demo becomes real without touching the API-key or funder layers.

In scope

  • Partner as an entity, distinct from a lender user
  • Facility limit, draws, headroom
  • Reserve deposits and absorption
  • Coverage gate on every draw

Deliberately out

  • Partner API keys, versioned routes, HMAC webhooks
  • KYB workflow (record the outcome by hand for now)
  • Funder-side accounting behind the reserve
  • Any borrower-facing change whatsoever
02

Schema

2 new tables, 1 column, 1 view
ObjectShape and purpose
lending_partnersid, name, custody_wallet, reserve_wallet, facility_limit, reserve_rate (default 0.10), cost_of_capital, kyb_status, status. One row per partner. Kasama is row one.
facility_eventsid, partner_id, kind (draw | reserve_deposit | reserve_absorb | repayment), amount, tx_hash, loan_id (nullable), idempotency_key, created_at. Append-only.
loans.partner_idNullable FK. Set when the loan is issued under a partner's license; NULL keeps the existing P2P path untouched. lender_user_id semantics do not change.
v_facility_stateView deriving drawn, reserve_balance, required, coverage, headroom from the event log. Never a mutable counter — same reason the loan book is reconciled on-chain rather than trusted.
 
-- the whole model in one expression
drawn            = sum(draw) - sum(repayment)
reserve_balance  = sum(reserve_deposit) - sum(reserve_absorb)
required         = drawn * partner.reserve_rate
coverage         = reserve_balance / nullif(required, 0)
headroom         = least(facility_limit - drawn,
                         reserve_balance / reserve_rate - drawn)   -- the gate
03

Functions

3 new edge functions

facility-draw

Body {partner_id, amount, reserve_top_up?, idempotency_key}. Computes state after the proposed draw; on pass, sends USDC to the partner's custody_wallet and appends a draw event with the tx hash.

Declines with 422 reserve_floor when coverage < 1.0 after the draw, naming the exact top-up required. This single rule is the product.

reserve-deposit

Verifies a real on-chain USDC transfer into reserve_wallet before crediting anything — the same verify-then-write pattern confirm-loan-payment already uses, including a write to used_payment_hashes so a hash can never be credited twice.

Never credits on a claim. Only a confirmed transfer moves the number.

facility-charge-off

Marks a partner loan as a loss, appends reserve_absorb for the outstanding principal, and blacklists the borrower through the existing kyc_blacklist + Didit list push that admin-refund-loan already performs.

If absorbing pushes coverage under 1.0, draws stop automatically — no separate flag to set or forget.
